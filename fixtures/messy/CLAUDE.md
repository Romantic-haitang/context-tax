# 项目约定

## 语言与风格
- 本仓库使用 TypeScript，禁止 any。
- 所有导出函数必须有 JSDoc。
- 变量命名使用 camelCase，常量使用 SCREAMING_SNAKE_CASE。
- 不要使用 default export，统一使用 named export。
- import 顺序：node 内置 → 第三方 → 本地，组之间空一行。

## 提交规范
- 提交信息使用 Conventional Commits。
- feat / fix / docs / refactor / test / chore，scope 必填。
- 一次提交只做一件事，超过 400 行请拆分。
- 不要在提交信息里写"优化了一下"，要写清楚优化了什么。

## 测试
- 所有新增逻辑必须有单元测试。
- 覆盖率不低于 80%。
- 不要在测试里 sleep，用 fake timer。
- 集成测试放在 tests/integration 下。

## 目录结构
- src/ 放源码，tests/ 放测试，scripts/ 放一次性脚本。
- 组件放 src/components，每个组件一个目录。
- 工具函数放 src/utils，按领域分子目录。

## 依赖
- 新增依赖必须先说明理由。
- 不要引入超过 100KB 的依赖，除非真的必要。
- 优先使用标准库。

## 代码评审
- 评审时优先关注正确性，其次可读性，最后风格。
- 风格问题交给格式化工具，不要在评审里争论。
- 每个 PR 至少一个人 approve。

## 错误处理
- 不要吞异常，catch 之后必须处理或重新抛出。
- 用户可见的错误信息不要说"出错了"，要说清楚发生了什么以及该怎么办。
- 日志分级：debug / info / warn / error，生产环境不输出 debug。

## 性能
- 避免在渲染路径里做重计算。
- 列表渲染必须带稳定的 key。
- 大数据量场景先做虚拟滚动，不要一上来就上 Web Worker。

## 安全
- 不要把密钥写进代码，用环境变量。
- 所有用户输入都要校验。
- SQL 一律使用参数化查询。

## 文档
- README 保持最新。
- 复杂逻辑写注释说明"为什么"，不写"是什么"。
- 每个模块顶部写一段模块职责说明。

## 其他杂项
- 不要用 moment.js，用 dayjs。
- 不要用 lodash 的全量引入。
- 时间统一用 UTC 存储，展示时转本地时区。
- 金额统一用整数分存储，不要用浮点。
- 图标统一用 lucide。
- 样式统一用 Tailwind，不要写内联 style。
- 不要在组件里写死中文文案，走 i18n。
- 提交前跑 lint 和 typecheck。
- pre-commit hook 已配置，不要跳过。
- CI 失败先本地复现，不要在群里问。
- 遇到不确定的产品需求，先问，不要自己猜。
- 删代码比加代码更需要理由。
- 保持简单，不要为了抽象而抽象。
